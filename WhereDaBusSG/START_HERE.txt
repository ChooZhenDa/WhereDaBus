TO VIEW THE SUBMITTED PROJECT

Extract Source_Data_Manual.zip and open the WhereDaBusSG folder. If you
cloned the repository, open its WhereDaBusSG application folder.
Double-click Setup.cmd. It starts Docker Desktop if needed. Docker Desktop
for Windows with Linux containers must be installed once.
The first build needs internet access. Setup loads the included data and
opens the website. On a fresh copy you can use it without an LTA key.
Morning crowding opens for service 860 at stop 59059 on 18 November 2026.
Use the menu for other features. USER_MANUAL.txt has two short demonstrations.

If this folder already has a valid live .env, Setup opens the existing site.
It keeps its route catalogue, fills an empty catalogue from the submission,
and adds missing samples within the database's retention period. If the
recorded morning has expired there, Setup opens the archived results.

OPTIONAL: SET UP LIVE ARRIVALS ON WINDOWS

Follow these steps if you want to fetch current predictions or collect new
observations. This workflow uses your own LTA account and separate databases.

1. If Docker Desktop is not yet installed, use the Windows installation
   instructions for Linux containers:
   https://docs.docker.com/desktop/setup/install/windows-install/
2. Open PowerShell in the application folder and run .\Setup.cmd --live.
   Enter your LTA DataMall AccountKey when prompted. The key is hidden as
   you type.
   For a key, use https://datamall.lta.gov.sg/content/datamall/en/request-for-api.html
3. Wait for the browser to open. Setup generates local database passwords,
   chooses a port and imports the route network. Use the address shown in
   the window. Select Live data to use this installation. Opening Live
   arrivals and choosing a stop displays current predictions.

Use .\Setup.cmd --live again if you need to change the saved key.

Live app controls
  Start.cmd         Reopen the live installation.
  Stop.cmd          Stop it and retain the data in Docker.
  Refresh-Data.cmd  Refresh the LTA stops and routes.
  Start-Live.cmd    Start and refresh the LTA stops and routes.

A valid key, internet access and a successful first static import are needed
for live use. For an HTTP 401 or 403, rerun .\Setup.cmd --live. For an
import failure, check the key and connection and rerun Refresh-Data.cmd.
Keep the generated .env and Docker volumes in place between runs. The .env
contains the private LTA key and database credentials. Keep it on your PC.

Live arrival features
  Search a stop in Live arrivals, or select two stops in Direct routes.
  Where available, routes show minutes until boarding, reported load and
  an estimated adult card fare for one direct ride. Feedback beside an
  upcoming arrival lets riders report a full, delayed or skipped bus.
  Use the same browser to change or clear a report. Other riders on this
  installation see the count for the same service, stop and advertised ETA.

Collect new history
  Start-Sampling.cmd starts the collector for the configured stops.
  Sampling-Status.cmd shows recent activity. Stop-Sampling.cmd ends
  collection. Keep Docker running and the computer awake while sampling.
  A live arrival lookup by itself does not record a historical sample.

  To inspect new readings, open Half-hour trends, choose a sampled stop,
  service and date range, then run the query. Morning crowding uses weekday
  samples between 07:00 and 08:59 Singapore time. A report can return zero
  observations if collection was off during that period.

Move live samples to another PC
  1. With the live app running, run Export-Samples.cmd. Find the resulting
     ZIP in sample-backups.
  2. Copy the ZIP to the target PC and complete live setup there.
  3. Drag the ZIP onto Restore-Samples.cmd, or run the launcher and enter
     the backup path. The import preserves original IDs and skips
     duplicates. The live installation uses 90-day retention. Older
     readings remain in the backup. The transfer holds arrival history;
     personal saved journeys and feedback stay on the original installation.

Development and database evidence
  Collect-Evidence.cmd records controlled database checks and query timings.
  EVIDENCE_GUIDE.txt describes these results. For a fresh live export, use
  submission-tools/READ_ME_FIRST.txt. The submitted snapshot and its audit
  evidence are already included in the review copy.
